## 0. 项目信息

| 项 | 内容 |
|---|---|
| Language | 简体中文 |
| Project Name | `unillm_platform` |
| 前端形态（已拍板） | FastAPI 直接托管的**内置 Web 控制台**：原生 HTML + 手写 CSS + 原生 JS，**无构建步骤、无外部 CDN、可离线** |
| 后端现状（既有能力，不改） | FastAPI + SQLAlchemy(SQLite) + Pydantic v2，33 个端点全部可用，53 测试通过、真实进程冒烟 13/13 |
| 使用场景（已拍板） | **小团队内网共享服务**（几位同事共用一台内网服务器），非多用户 SaaS |
| 原始需求复述 | 平台后端功能已完整（数据接入 → 标注 → 微调 → 评测 → 推理 五段闭环 + OpenAI 兼容推理接口），但**没有前端界面**，用户只能通过 Swagger 操作；且**没有鉴权、没有一键启动**。本期目标：给它一个**可登录、可操作、可离线私有化部署**的内置 Web 控制台，让它从「API 项目」变成「产品」。 |

### 硬底线（来自上一轮重构，贯穿全篇，不可妥协）

> 平台把「**不造假**」作为产品原则。任何界面都**不得掩盖**降级与不可用状态。

| 场景 | 后端事实 | 界面必须呈现 |
|---|---|---|
| 未装 vLLM，推理走占位后端 | 响应体 `backend: "mock"`；占位文本以 `[MOCK]` 开头 | 全局**醒目**横幅 + 每次推理结果上的徽章，明确「当前是占位后端，非真实模型」 |
| 未装 torch，困惑度算不出 | `perplexity.available = false` + `reason` | 指标卡片显示「**不可用**」并原样展示原因与启用方式，**禁止**显示估算值/占位数字 |
| 微调未装 GPU 依赖 | 任务 `failed` + `error_message` 指向 `requirements-gpu.txt` | 如实显示失败与原因，**禁止**显示为「训练完成」 |
| 模型未真正加载 | `/api/model/load` 降级返回 `status=degraded` | 显示「已切换占位后端」，**不得**显示为「加载成功」 |

## 1. 产品定位与一句话价值主张

**定位**：一款可离线私有化部署、开箱即用的**小团队大模型研发控制台**——把「数据接入 → 标注 → 微调 → 评测 → 推理」五段流程收敛到一个浏览器界面里，并对「结果是真模型产出还是占位/不可用」保持完全诚实。

**一句话价值主张**：

> **一条命令起服务、一个浏览器页面跑通大模型研发全流程——并且永远告诉你，看到的结果是真的还是占位的。**

补一句给决策者的：本产品的差异化**不在功能数量**，而在于对「私有化 / 离线 / 不造假」三件事的坚持——这是它相对通用云平台的核心取舍。

## 2. 目标用户画像

| 画像 | 角色 | 技术背景 | 核心诉求 | 对本产品的期待 |
|---|---|---|---|---|
| **A. 算法工程师（主力用户）** | 负责微调与评测 | 熟悉 Python / 模型训练，但**不想用 Swagger 手搓 JSON** | 快速搭出「导入数据 → 加载模型 → 评测对比」的闭环 | 界面要能少写胶水代码，指标要**真实可信**（宁愿显示「不可用」也不要假数字） |
| **B. 数据/业务同事（协同用户）** | 负责数据清洗与标注 | 会用 Excel、会点网页，**不懂命令行** | 把业务问答数据导入、把没答案的样本标上答案、导出一份能用的训练集 | 操作要傻瓜化；出错要用**人话**说清哪一步错了、怎么改 |
| **C. 团队技术负责人（部署与把关者）** | 搭建并维护这套内网服务 | 熟悉部署与运维，关注安全与可信度 | 一键部署给团队用；能控制访问；能一眼看出「这套环境到底能不能跑真模型」 | 需要一层**轻量鉴权**；需要**健康/降级状态**一目了然，避免同事误信占位结果 |

> 设计含义：控制台的「阅读门槛」要低到 B 能用，但「信息密度」要够到 A/C 满意。降级状态主要服务于 C 的把关诉求。

## 3. 核心使用场景（端到端）

### 场景 1｜算法工程师：搭一条最小闭环（导入 → 加载 → 推理 → 评测）
- **角色**：算法工程师 A
- **触发时机**：刚拿到一批业务问答数据，想快速验证「当前环境+模型」能不能用
- **操作路径**：
  1. 打开控制台，Token 登录；首页**首先**看到环境状态（真实后端 / 占位后端）
  2. 进入「数据集」→「导入数据」，上传 `qa.jsonl`（自带 `output` 字段）→ 数据集出现，样本数 > 0
  3. 进入「模型」→「注册模型」→「加载模型」；若环境降级，**立即**看到「已切换占位后端」提示
  4. 进入「推理试验台」，发一条对话，看到回复顶部带 `[MOCK]` 徽章 → 明确知道当前不是真模型
  5. 进入「评测」→ 新建评测（选该数据集、勾选 `exact_match`/`token_f1`/`latency`）→ 运行 → 查看指标
- **达成结果**：在**不写一行代码**的前提下，判断出「这套环境现在能干什么、结果可不可信」，并拿到一份真实的指标报告。

### 场景 2｜数据同事：把没答案的样本补齐并导出训练集
- **角色**：数据/业务同事 B
- **触发时机**：导入的数据里有一部分样本没有参考答案，需要人工补
- **操作路径**：
  1. 登录（B 只需拿到团队共享的 Token）
  2. 「数据集」→ 查看某数据集，看到「已标注 / 待标注」数量
  3. 「标注」→ 新建标注任务 → 进入标注工作台：系统逐条给出 `instruction + input`，B 在输入框写 `output` → 提交 → 自动跳到下一条
  4. 顶部进度条显示 `completed / total`；全部完成后任务状态变「已完成」
  5. 回到「数据集」→「导出训练集」→ 下载 JSONL
- **达成结果**：拿到一份「只含已完成样本」的训练集，可直接喂给微调或评测。

### 场景 3｜团队成员：评估一个候选模型的好坏
- **角色**：算法工程师 A（或 C 把关）
- **触发时机**：想对比「微调后模型」与「基线模型」在一批固定样本上的表现
- **操作路径**：
  1. 「评测」→ 新建评测，绑定 `model_id` + `dataset_id`，勾选指标
  2. 运行 → 结果页显示 `exact_match`、`token_f1`（字符级）、`latency`（min/avg/p50/p95/max）
  3. 若勾选了 `perplexity` 但环境未装 torch → 该卡片显示「**不可用：未安装 torch / transformers**，启用方式：…」
  4. 结果页顶部标明「本次结果来自：占位后端（不可作为模型能力结论）」
- **达成结果**：拿到一份**带可信度标注**的评测结论，不会把占位结果误当成模型能力。

### 场景 4｜技术负责人：把服务部署到内网并控制访问
- **角色**：团队技术负责人 C
- **触发时机**：要让几位同事一起用
- **操作路径**：
  1. 在服务器 `pip install -r requirements.txt`
  2. 在 `config.yaml` 里设置一个团队 Token（或经环境变量注入）
  3. 一条命令启动服务，浏览器打开内网地址 → 出现登录页
  4. 把 Token 发给同事；同事登录后即可操作，未登录者看到的是登录页而非数据
- **达成结果**：一个受 Token 保护、内网可访问、无需外网依赖的共享服务。

### 场景 5｜算法工程师：发起一次微调并如实看到结果
- **角色**：算法工程师 A
- **触发时机**：数据已备好，想试跑一次 LoRA 微调
- **操作路径**：
  1. 「微调」→ 新建任务（选 `model_id` + `dataset_id`）→ 启动
  2. 任务列表实时显示 `status`（pending/running/completed/failed）与 `progress`（%）
  3. 若环境缺 GPU 依赖 → 任务显示 `failed`，展开可见**错误原因**与「需 `requirements-gpu.txt`（Linux+CUDA）」
  4. 若需中止 → 点「取消」→ 显示「已发送取消信号；已进入的训练 step 无法安全中断」（如实说明软取消语义）
- **达成结果**：清楚知道「任务编排链路可用，但真实训练需要 GPU 环境」这一事实，不被假成功误导。

## 4. MVP 功能范围

### 4.1 做什么（本期交付）

按控制台**页面**组织。每页对应一组既有后端端点，不新增后端能力。

| 页面 | 本期交付内容 | 依赖的既有端点 |
|---|---|---|
| **P-01 登录页** | 输入团队 Token → 登录；校验失败给出明确提示 | （需一个受保护的校验探针，见 §7） |
| **P-02 总览 / 控制台首页** | 环境状态卡（真实/占位后端）、已注册/已加载模型数、数据集数、快捷入口；**降级横幅**常驻 | `GET /health`、`GET /api/model/backend` |
| **P-03 数据集** | 列表、上传导入（json/jsonl/csv）、删除、查看详情（名称/样本数/来源/时间）、**导出训练集** | `GET /api/data/list`、`POST /api/data/import`、`GET /api/data/{id}`、`GET /api/data/{id}/export`、`DELETE /api/data/{id}` |
| **P-04 模型** | 列表、注册、加载、卸载、**后端状态显示**（真实/占位） | `GET /api/model/list`、`POST /api/model/register`、`POST /api/model/load`、`POST /api/model/unload`、`GET /api/model/backend`、`DELETE /api/model/{id}` |
| **P-05 推理试验台** | 对话式（chat）与文本补全（completion）两种模式；可调 temperature/top_p/max_tokens；结果区**强制**显示 `backend` 徽章 | `POST /v1/chat/completions`、`POST /v1/completions`、`GET /v1/models` |
| **P-06 评测** | 新建评测、运行、结果页（指标卡 + 指标口径说明 + 不可用指标如实呈现 + 结果可信度标注） | `POST /api/evaluate/create`、`POST /api/evaluate/{id}/run`、`GET /api/evaluate/list`、`GET /api/evaluate/{id}/result` |
| **全局框架** | 左侧导航、顶栏（环境状态灯 + 退出登录）、统一空状态 / 错误 / 加载态 / 降级态 | — |

> **为什么这六页是 MVP 的最小集合**：它们构成一条**最短可信闭环**——登录 → 看环境是否可信 → 导入数据 → 加载模型 → 亲自试一次推理 → 跑一次真实评测。任何再少，产品就退化回「Swagger 套壳」。

### 4.2 不做什么（明确排除项 + 理由）

| 排除项 | 理由（防止范围蔓延） |
|---|---|
| **不做多用户账号体系 / 注册 / 密码 / 权限分级** | 已拍板是「小团队共享服务」，单 Token 即可覆盖；引入账号体系=做 SaaS，成本远大于收益。 |
| **不做数据隔离（按人/按目录）** | 同上，内网小团队默认互信；隔离属于多租户范畴。 |
| **不做流式输出（stream=true）** | 后端**显式**返回 400 不支持。前端做「假流式打字机」属于**违反不造假底线**，坚决不做。 |
| **不做训练曲线 / 实时 loss 可视化** | 真实训练需 GPU 依赖，本环境无法产出真实曲线；做出来只能靠假数据，属于**无效且违背底线**的功能。 |
| **不做困惑度的「估算值」** | 硬底线：拿不到就显示「不可用 + 原因」，不允许估算。（对应的是「做对」，不是「不做」） |
| **不做模型市场 / 在线下载权重** | 与「离线私有化」定位冲突，且需要外网。 |
| **不引入前端框架 / 构建工具 / 外部 CDN** | 已拍板原生 HTML+手写 CSS；离线内网要求零外部资源依赖。 |
| **不做并发限流 / 任务队列 / 排队可视化** | 后端尚未实现；前端造「队列」是假象。列为 P2 前置需求。 |
| **不做移动端专门适配** | 使用场景是内网桌面运维/研发；做到「窄屏可用」即可，不做专门 App 体验。 |
| **不做大文件在线预览 / 数据行编辑** | 超出 MVP；数据编辑器是另一个量级的产品。 |
| **不做标注任务的多人分配 / 质检流** | MVP 只做「单人领取—标注—提交」最小闭环；分配与质检是 P2。 |
| **不做一键启动脚本之外的部署编排（Docker/K8s）** | 本期只保证「pip install + 一条命令启动」；容器化交给部署阶段。 |

## 5. 需求池（P0 / P1 / P2）

> 优先级定义：**P0 = MVP 必须**；**P1 = 重要可延后**；**P2 = 未来**。

### P0 —— MVP 必须

| # | 需求描述 | 后端端点 | 验收标准（可验证判据） |
|---|---|---|---|
| P0-1 | **Token 登录**：未登录时访问任何控制台页面都被拦到登录页；输入正确 Token 后进入控制台 | （受保护校验探针，见 §7） | ① 未带 Token 访问受保护页 → 显示登录页，**不泄露**任何业务数据；② 错误 Token → 提示「Token 无效」且停留登录页；③ 正确 Token → 进入总览页 |
| P0-2 | **登录态保持**：登录后刷新页面仍保持登录 | 同上 | 刷新页面后仍在控制台；退出登录后回登录页且本地凭证被清除 |
| P0-3 | **未授权拦截**：接口返回 401/403 时统一处理 | 全部受保护端点 | 收到 401 → 清除本地凭证 + 提示「登录已失效，请重新登录」并跳登录页；收到 403 → 提示「Token 无权访问」且不清除登录态 |
| P0-4 | **全局降级横幅**：当后端为占位/mock 时，控制台**每一页顶部**常驻醒目提示 | `GET /health`（`degraded`）、`GET /api/model/backend` | 当 `is_real_model=false` 时，横幅文字包含「**当前为占位后端，非真实模型**」；当 `is_real_model=true` 时横幅消失、顶栏状态灯为「真实后端」 |
| P0-5 | **总览首页**：展示环境状态、已注册/已加载模型数、数据集数、快捷入口 | `GET /health` | 首页展示的 `models_loaded`、`registered_models` 与 `/health` 返回值**一致**（非硬编码 0） |
| P0-6 | **数据集列表 + 空状态** | `GET /api/data/list` | 无数据时显示空状态文案与「导入数据」引导按钮；有数据时列出名称/样本数/来源/创建时间 |
| P0-7 | **数据集导入**：上传 json/jsonl/csv，填写名称 | `POST /api/data/import` | ① 上传合法文件 → 列表新增该数据集且样本数 > 0；② 上传非法扩展名 → 显示后端返回的「不支持的文件类型」错误；③ 超过 100MB → 显示「超过上限」；④ 导入失败后**不残留**空数据集（列表数量不变） |
| P0-8 | **数据集删除** | `DELETE /api/data/{id}` | 删除前二次确认；删除后从列表消失 |
| P0-9 | **导出训练集** | `GET /api/data/{id}/export` | ① 有已完成样本 → 触发下载 JSONL；② 无可导出样本 → 显示后端结构化提示（「没有已标注样本，无法导出」），**不产生空文件** |
| P0-10 | **模型注册** | `POST /api/model/register` | 填写名称后注册成功，模型出现在列表，`is_loaded=false` |
| P0-11 | **模型加载 / 卸载 + 降级如实呈现** | `POST /api/model/load`、`POST /api/model/unload` | ① 加载降级（`status=degraded`）→ **不得**显示「加载成功」，须显示「已切换到占位后端」及 `reason`；② 加载真实成功（`status=success`）→ 显示「加载成功」；③ 加载后 `/health` 的 `models_loaded` 与列表一致 |
| P0-12 | **推理试验台（含 backend 徽章）** | `POST /v1/chat/completions`、`POST /v1/completions`、`GET /v1/models` | ① 每条回复旁显示 `backend` 值；② 当 `backend="mock"` 时回复文本可见 `[MOCK]` 前缀且界面有「占位输出」标注；③ 传 `stream=true` 被后端 400 时，界面显示「暂不支持流式输出」而非静默失败；④ 模型下拉来自 `/v1/models`，未注册时如实提示「未注册模型」 |
| P0-13 | **评测：新建 + 运行 + 结果** | `POST /api/evaluate/create`、`POST /api/evaluate/{id}/run`、`GET /api/evaluate/{id}/result` | ① 结果页展示 `exact_match`、`token_f1`、`latency`（min/avg/p50/p95/max）；② 缺数据时后端 400 → 界面显示其 `message`（如「请传入 test_data 或指定含参考答案的数据集」）；③ 结果页标注 `backend_is_real_model`：为 false 时显示「**占位后端结果，不可作为模型能力结论**」 |
| P0-14 | **不可用指标如实呈现** | 评测结果中的 `perplexity` | 当 `available=false` 时，卡片显示「**不可用**」+ 原样展示 `reason` 与 `how_to_enable`；**不得**出现任何数字或进度条替代 |
| P0-15 | **统一空状态 / 加载态 / 错误提示** | 全部页面 | 每个列表页无数据均有空状态文案；请求进行中显示加载指示（禁用按钮防重复提交）；请求失败显示错误条且**保留可重试入口** |
| P0-16 | **离线可用**：控制台不请求任何外部域名 | 静态资源 | 断网（或仅内网）环境下，页面样式与脚本全部正常，浏览器控制台**无**外部 CDN 请求失败 |

### P1 —— 重要可延后

| # | 需求描述 | 后端端点 | 验收标准 |
|---|---|---|---|
| P1-1 | **标注任务列表 + 新建任务** | `POST /api/annotation/task`、`GET /api/annotation/task/list`、`GET /api/annotation/task/{id}` | 对某数据集建任务成功，列表显示 `total_items / completed_items / status` |
| P1-2 | **标注工作台**：取一条待标注 → 提交 → 取下一条 | `GET /api/annotation/task/{id}/next`、`POST /api/annotation/submit`、`GET /api/annotation/task/{id}/progress` | ① 提交后进度条 `completed/total` 增加；② 无待标注项时 `next` 返回 `status=completed` → 显示「已完成全部标注」；③ 提交空答案被拦截 |
| P1-3 | **标注样本列表（按状态过滤）** | `GET /api/annotation/task/{id}/items` | 可按 `pending/completed` 过滤查看 |
| P1-4 | **微调任务：新建 + 启动 + 状态轮询 + 取消** | `POST /api/finetune/create`、`POST /api/finetune/{id}/start`、`GET /api/finetune/list`、`GET /api/finetune/{id}/status`、`POST /api/finetune/{id}/cancel` | ① 状态与 `progress` 需**轮询自动刷新**；② `failed` 时展开可见 `error_message`（含 GPU 依赖指引）；③ 取消返回 `status=cancelled`，界面显示「软取消」说明；④ 任务已 running 时再启动 → 显示「已在运行」 |
| P1-5 | **创建空数据集** | `POST /api/data/create` | 可创建无样本数据集，供后续标注/导入 |
| P1-6 | **评测内联样本（test_data）** | `POST /api/evaluate/{id}/run` | 可在界面上粘贴 JSON 样本直接评测，无需先建数据集 |
| P1-7 | **评测列表与历史** | `GET /api/evaluate/list` | 展示历史评测及各自 `status`，可回看结果 |

## 7. 鉴权方案的产品侧定义

> 本节只定义**产品行为**（用户看到什么、怎么交互）；具体中间件/校验实现由架构师决定。

| 方面 | 产品侧定义 |
|---|---|
| **Token 从哪来** | 由**部署者**在配置中设置（`config.yaml` 的鉴权配置项，或经环境变量注入）。团队**共用一个 Token**。控制台不提供 Token 的注册/修改入口。 |
| **控制台怎么登录** | 登录页仅一个输入框 + 「进入控制台」按钮。用户粘贴 Token → 前端用它调用一个**受保护的校验探针**；探针通过 → 进入控制台；失败 → 原地显示「Token 无效」。 |
| **登录态怎么保持** | Token 保存在浏览器本地（localStorage），后续每个请求自动附带。刷新页面**保持登录**，无需重输。 |
| **请求怎么带 Token** | 所有对后端 API 的请求统一附带该 Token（具体请求头名由架构师定，产品侧只要求「统一、且不放在 URL 里以免泄露到日志」）。 |
| **未登录时看到什么** | 访问任何控制台页面 → **一律重定向到登录页**。登录页**不展示**任何业务数据、模型名、数据集等敏感信息；顶栏导航隐藏。 |
| **接口被拒时怎么提示** | 统一拦截：<br>· **401（未认证）** → 清除本地 Token + 顶部提示「登录已失效，请重新登录」→ 跳登录页；<br>· **403（无权限）** → 提示「Token 无权访问该操作」，**不清除**登录态；<br>· **网络/服务不可达** → 提示「无法连接服务，请确认服务已启动」。 |
| **是否需要「退出登录」** | 需要。顶栏提供「退出登录」→ 清除本地 Token → 回登录页。 |
| **范围边界** | 本期**不做**：注册、密码、角色权限、多 Token、数据隔离、登录审计。（理由见 §4.2） |

**部署侧一句话（面向 C）**：设置一个团队 Token → 启动服务 → 把 Token 与内网地址发给同事。唯一的安全前提是「内网可信 + Token 不外泄」。

## 8. 待确认问题（进入架构设计前需澄清）

| # | 问题 | 影响 | 建议默认 |
|---|---|---|---|
| Q1 | **Token 存 localStorage 是否可接受？** 是否要求登录态过期时间 / 「记住我」开关？ | 影响鉴权体验与安全取舍 | 默认 localStorage + 不设过期（内网共享场景足够） |
| Q2 | **静态页面本身（控制台 HTML）是否也要鉴权保护？** 还是仅 API 受保护、页面公开但数据靠 API 拦？ | 影响架构与安全边界 | 默认：页面可公开加载，**数据全部靠 API 鉴权**拦（更简单） |
| Q3 | **鉴权是否需要「可关闭」开关？** 例如本地单机开发时想免 Token | 影响配置设计与本地开发体验 | 默认：提供开关，默认开启鉴权 |
| Q4 | **Token 的传递方式与名称**由架构师定为请求头（如 `Authorization: Bearer` 或 `X-API-Token`）——需确认是否有既有约定 | 影响前后端契约 | 待架构师定 |
